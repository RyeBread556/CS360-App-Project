# CS360-App-Project

Project Reflections

**Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?**

The goal of the EventTracker application was to provide users with a simple and dependable method of managing their 
personal events, schedules, and appointments. It was designed to address the need for a tool to organize scheduling
allowing users the ability to create their accounts, have a secure login, store events within a database, and have
a robust SMS notification reminder system. Targeted users are busy students, professionals, parents, or even everyday users that had schedule needs. It was intended to be ease of use and simple/functional helping users be organized and preventing missed events.

**What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?**

Several different screen designs were necessary for potential users, the app included a login screen where users can create their accounts, add them to the database, then securely access that account. The next scree would layout and organize events within a grid-like layout, it would be easy to read and navigate making it easy for a user to understand their itinerary. The next screen was a add event screen, this allowed users to manage their events by entering information like date/time, name, description. The next screen was for SMS notifications, where it would ask for user permission to enable SMS notifications for users, essentially a reminder system that worked even outside the application screen. The design was oriented to be simple and accessible with a logical workflow from login to managing events, buttons were consistent and clear increasing readability and usability. 

**How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?**

I approached creation by first developing the UI, then adding the needed functions afterwards, by breaking up the overall project into smaller manageable tasks, development and testing was easier allowing to both to be done in a step-by-step manner. From there the database was created first before making the login screen ensuring that the database first worked and would store data, then I moved on to other features that needed it like event creation and SMS permissions. The main strategy here was using incremental development, which is somthing that i have used in the past and can continue using in the future, the approach is useful for identifying issues early, and made feature development easier. When I eventually encounter more complex and larger software products this will be useful for maintaining organization.


**How did you test to ensure your code was functional? Why is this process important, and what did it reveal?**

Testing was done in an on-the-go basis using the android emulator, after playing around and implementing every new feature I would make sure that it would run to begin with and two, meet the expectations on the emulated phone screen. Testing was especially done on features and screens like the login screen, ensuring that the system would recognize a login, as well as save it. This was the same for event creation; it was important to test that events were saved as well as all its associated characteristics that a user might put in. This process of testing is important because it reveals issues early, making changes both earlier and later easier. the more finalized a app gets the harder it is to fix issues without affecting functionality or having to make rehauls. A few issues were identified because of this process, I had problems with the login screen where it wouldn't allow a user to login even after creation, because this was found early debugging was easier, this was true for screen navigation i had an issue where the app would not proceed to the next screen after login.

**Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?**

The biggest issue I would say for me was trying to not only understand the logic to make the different functionalities work but trying to go back and connect all of them to each other making them work together. having to a login screen, then making a database that in turn worked in tandem together was difficult and I spent a lot of time on it. This of course, continued when you would try to do this again making changes to one section which would then affect another. Like so many projects I've done before, to overcome these challenges, it was important to work step-by-step, it's easy to jump the gun and get lots in so many development areas at once without completing others, isolating each issues and fighting the urge to fix all of it at once made it much easier to handle, different features relied on others so careful testing and debugging alongside were important.
